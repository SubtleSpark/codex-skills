# 知识回流 PR

手动调用 → 整理当前任务相关知识 → 对照最新主库 → 检查文本与知识冲突 → 提交 PR → 结束。

## 执行范围

- 只处理当前知识库向同一知识库主分支的贡献，不自动从其他项目收集知识或寻找另一个接收库。
- 仅由用户明确触发，不因任务结束或发现可沉淀内容自动运行，不添加后台任务、队列或回流日志。
- 一次只整理本次任务相关成果。历史材料按核对需要定向读取，不扫描工作树长期积累的所有内容。
- 用户要求完成回流 PR 时，连续完成整理、验证、提交、推送和创建或更新 PR，不逐步重复确认。用户若明确限制为讨论或候选整理，遵循该限制。
- 完成点是检查通过的普通 PR。合并 PR、同步或清理源工作树、扩大材料范围属于另外明确要求的工作。
- 不绑定机器路径、账号、仓库名或分支名；使用当前环境已有的 Git、托管平台 API 或 CLI。必要能力缺失时报告限制，不自动安装工具。

## 确认上下文

读取当前知识库的贡献规则、入口和相关页面，遵循其知识范围、收录标准、证据及文件约定。

结合实际 Git 状态确认当前工作区及其远端主仓库；不能仅凭某个目录名或 `origin` 名称确定目标。有多个无法排除的合理目标时再询问。目标分支按用户或仓库约定确定，否则读取远端默认分支。

结合本次任务上下文和相关提交、暂存、未暂存、未跟踪材料提取候选。普通 diff 不含未跟踪文件内容；文本差异也不等于知识增量。每项候选应能说明结论、适用条件、依据以及对未来任务的作用。

## 与最新主库整合

通过 fetch 或远端 API 取得目标分支当前提交及相关内容；不要求先将主库合入源工作树。对照相关页面与未合并 PR：

| 情况 | 处理 |
| --- | --- |
| 本地落后或保留旧表述 | 识别版本差异，不作为新发现写回；新的反证仍按证据评估。 |
| 主库已覆盖同一结论 | 跳过；仅换措辞不算新知识。 |
| 新增条件、证据、反例或边界 | 优先补充最接近的已有页面。 |
| 有依据的纠正 | 说明纠正的依据和影响，保留必要的纠正说明。 |
| 结论冲突 | 核对场景、版本和依据；条件不同就写清条件，无法判定就保留分歧与未知。 |

同一贡献已有 PR 时，在授权范围内继续完善。其他相关 PR 作为提案处理，说明重叠、依赖或分歧，不将其视为主线事实，也不覆盖他人的工作。已合并 PR 用于理解历史，是否重复仍以当前主库内容为准。

遵循库内原始证据保存规则，不为整理方便改写原件。AI 共识、review 或 PR 合并不证明结论正确。没有合适增量时简短说明并结束，不制造空 PR。

## 形成贡献

默认从最新目标提交准备干净的短期贡献分支，使用安全且空闲的独立工作区或远端编辑能力，保留正在使用的源工作树。

已有任务分支的全部拟合入变化及拟推送历史都属于本次贡献时，可以复用。独立完整的提交可以挑选；混杂改动按内容选择或重写。选择 stage 文件不能排除已有无关提交；检查最终 diff 时也要核对拟发布历史。

在主库当前页面上编辑，保留已有有效信息，按需修复链接和索引；不要整页复制旧工作树覆盖主库的新内容。成果应无需原任务上下文即可理解和核对。

不为整理而自动 stash、reset、clean、rebase 或覆盖活跃源树，不要求提交源树全部内容。发现新结论影响当前任务正在使用的判断时，指出具体影响。

## 检查并提交

- **文本冲突**：通过 Git 或托管平台检查贡献分支能否与最新目标提交合并；需要时在贡献分支或隔离环境中解决。
- **知识冲突**：检查修改页面及直接相关结论的矛盾、重复、过时内容和条件遗漏。文本能自动合并不代表知识相容。
- 有充分证据就纠正；证据不足可以提交明确记录分歧的变更，不能随意选边写成确定事实。
- 解决后重读完整页面与 diff，核对依据、适用范围、发布内容及历史，排除凭据和无关私有材料；按库规则完成链接、索引、格式及必要验证。
- 提交前复查目标分支及相关 PR。目标前移后重查文本合并，并复核受影响的知识；记录检查对应的目标和贡献提交。关键检查无法完成时报告具体阻塞，不以未完成的 Draft PR 代替本次交付。
- 沿用仓库分支和提交习惯。PR 说明知识变化、依据、验证及剩余分歧，不粘贴完整任务过程。
- 创建或更新 PR 后核实远端目标、分支和实际 diff；可用时附加到当前聊天。写入结果不明确时先核对远端状态，避免重复 PR 或覆盖并发提交。

反馈 PR 链接、实际贡献、验证结果及未解决事项，然后结束。不要自动合并、持续跟踪 PR 或同步源工作树。
