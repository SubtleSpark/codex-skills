# 尝试归档

检查 → 安全清理 → 复查 → 归档。用户调用本 Skill 后，在下列范围内直接执行，不逐项重复确认；仍遵守用户限制及环境审批。讨论、审查或修改本 Skill 不算执行请求。

## 1. 复用已有检查

先读取同一插件内的 [session-archive-checker](../session-archive-checker/SKILL.md)，按它的范围、证据要求和判定规则完成检查，不另写一套标准。相对路径以本文件所在目录为准；引用不可读取时停止，不凭记忆代替。

检查阶段遵守它的只读边界，无需单独输出报告或改标题；以下步骤才执行本 Skill 授权的动作。原 Skill 单独调用时仍只检查。

只有完整检查结论为“可归档”才继续。结论为“暂不建议归档”“需要确认”，或只完成局部检查时，说明原因并结束；不为通过检查而补做业务、测试或修改验收要求。

## 2. 清理明确安全的临时项

动手前确认当前 session 身份与状态；已经归档则直接结束，不再清理。核对环境正式提供的归档工具或指令及其副作用。能力缺失、目标不明或会造成未经授权的成果删除时，不清理、不归档，说明限制。不能通过删除会话文件、手改数据库或移除 worktree 冒充归档。

只清理检查中发现的可选整理项，且必须同时满足：本次 session 创建、未被 Git 跟踪或暂存、用途已结束、可重建、用户未要求保留、不被其他任务使用，也不再是必要的验证或排错证据。通常是普通日志、一次性脚本和中间文件。

逐个核对确切路径及当前状态；优先使用现有的可恢复删除能力，否则只删除满足上述条件的普通文件。不跟随符号链接，跳过仍在写入或检查后已变化的目标；不用通配符、整目录递归删除或 `git clean`。本次生成、ignored、untracked 都不能单独作为删除理由。

正式成果、源码、用户材料、标准缓存及归属或用途不明的文件原样保留。未提交改动也保留；不 stage、commit、push、合并 PR、改 ignore、回滚或停进程。清理失败或不能安全处理的可选项，保留并说明，不强行处理，也不因此单独阻止归档。

## 3. 复查并归档

清理后按同一检查规则复查受影响内容，确认成果仍在、先前检查仍有效。出现新要求、内容变化或关键疑问时重新评估；不再满足“可归档”就停止。发生误删或成果受损时保留证据并报告，不能继续归档。

归档是最后一个动作。先简短记录已清理和保留的事项，再用已确认的正式能力归档当前 session；不另行归档其他 session，不删除 branch 或 worktree。若归档会结束本轮，提前说明“检查通过，将尝试归档”，不要提前声称成功。

只有成功回执或归档状态能支持“已归档”。失败或结果不明就如实说明；重试前先核对状态，不盲目重复操作。

边界不清时参考[执行案例](references/examples.md)；通用的归档判断仍以原检查 Skill 为准。
