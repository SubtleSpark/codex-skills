# 执行案例

以下是预期行为，不是已执行的模型测试。除特别说明外，用户已调用 `$try-archive`，完整检查通过，环境支持归档当前 session。通用判定不在这里重复，见 [session-archive-checker](../../session-archive-checker/SKILL.md)。

| 场景 | 预期行为 |
| --- | --- |
| 只问“这个会话能归档吗”。 | 使用原检查 Skill，不清理、不归档。 |
| 要求编写或修改 try-archive。 | 只修改 Skill，不把开发请求当成当前会话的归档授权。 |
| 本次创建的未跟踪 debug.log 已无用途，可重建且不再作为证据。 | 清理该文件，复查后归档。 |
| 代码已保存且验证完成，但没 commit；任务没有要求提交。 | 保留改动，不自动提交；其他检查通过后归档。 |
| ignored 目录中有用户要求保留的报告，旁边有一个来源不明的文件。 | 两者均保留；文件存在本身不阻止归档。涉及交付的疑问则交回原检查规则判断。 |
| 临时路径是符号链接、被其他任务使用，或检查后内容已变化。 | 不删除；重新判断变化是否影响归档，不能直接忽略新风险。 |
| 已确认可选的日志因权限问题无法删除。 | 保留并说明，不提权或强删；无其他问题时仍可归档。 |
| 下载仍未完成，且本任务要求交付完整数据；或约定测试仍失败。 | 检查不通过，不清理、不归档，也不把补跑任务当作整理。 |
| 原检查 Skill 不可读取、只做了局部检查，或关键结果无法核实。 | 停止，不自行拼凑标准放行。 |
| 当前 session 身份无法确认，或环境没有正式归档能力。 | 不清理、不归档；报告具体限制，不改会话存储或删除 worktree。 |
| 清理后发现成果被误删。 | 停止并报告，不用归档掩盖问题。 |
| 归档返回失败或没有明确结果，随后再次调用本 Skill。 | 先查询当前状态；已归档则结束，未知则报告，不能声称成功或盲目重复。 |
